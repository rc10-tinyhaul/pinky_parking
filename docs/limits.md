# 실측 한계 분석

실물 Pinky Pro로 시연 시나리오(출차, 트랙 주행, 차선 변경, 주차)를 돌리며 확인한 한계입니다. 측정 방법과 설정별 원자료는 [tuning_log.md](tuning_log.md)에 있습니다.

- **실물** 칸이 비어 있으면 아직 재지 않은 것입니다.
- **시뮬레이션** 값은 실물 측정 전에 본 것으로, 실물과 같다는 근거가 아닙니다. 시뮬레이션과 실물은 Nav2 설정부터 다릅니다(주시 거리 0.6 m 대 0.2 m, 회전 1.0 대 0.8 rad/s).

## 요약

| 항목 | 시뮬레이션 | 실물 | 시연·최종 프로젝트에 주는 영향 |
|---|---|---|---|
| 주차 정차 오차 (거리) | 평균 19~34 mm | | |
| 주차 정차 오차 (방향) | 평균 5~7°, 최대 12° | | |
| 트랙 경로 오차 | 평균 9~17 mm, 최대 38~49 mm (1회씩) | | |
| SLAM 지도 치수 오차 | 해당 없음 | | |
| 마커로 되찾은 위치의 오차 | | | |
| 시나리오 성공률 | smoke test 3회 중 2회 | | |

## 1. 위치 추정

| 한계 | 근거 | 실물 확인 |
|---|---|---|
| 경기장 바닥은 테이프뿐이라 라이다에 보이지 않습니다. 위치는 교실 벽·가구 지도(AMCL)와 바퀴 기록, 바닥 ArUco 마커에 기댑니다 | 구조상 | |
| 경기장 판을 옮기거나 장소가 바뀌면 벽 지도를 다시 만들어야 합니다 | 구조상 | |
| 사람이 오가면 라이다가 사람을 벽으로 보고 위치가 튈 수 있습니다 | SLAM 설정을 보수적으로 바꾼 이유(`slam_params`) | |
| 화면 가장자리에 걸린 마커는 꼭짓점이 잘려 방향이 크게 틀립니다. 이런 마커는 쓰지 않게 걸렀습니다 | 시뮬레이션에서 방향 최대 28° | |
| 관제 API와 궤적 파일의 위치는 마지막 `amcl_pose`라, 로봇이 멈추면 새로 나오지 않아 마지막 몇 cm를 놓칩니다 | 시뮬레이션 주차에서 실제 18 mm일 때 157 mm로 나옴. 그래서 정차 오차는 줄자로 잽니다 | |

## 2. 주행과 주차

| 한계 | 근거 | 실물 확인 |
|---|---|---|
| Nav2는 도착 허용 범위(주차 3 cm, 약 5°)에 들면 바로 멈춰, 정차 오차가 허용 범위 가장자리에 몰립니다 | 시뮬레이션 10번 칸 10회, 평균 19~34 mm | |
| 마지막 직선 진입을 관제가 직접 몰아 봤지만 정차 오차가 줄지 않았습니다(브랜치 `syaseuta/precise-park`에 보관) | 시뮬레이션 | |
| 경기장 차선의 빈 공간은 170 mm(차선 폭 190 mm, 테이프 20 mm)라, 트랙은 경유점이 아니라 차선 중심선 경로를 따라가게 했습니다 | 경기장 도면 | |
| 트랙 주행이 가끔 "장애물 때문에 더 가지 못해" 멈춥니다 | smoke test 3회 중 1회(2026-11-24, 시뮬레이션). 원인 미확인 | |

## 3. 통신과 하드웨어

| 한계 | 대응 | 실물 확인 |
|---|---|---|
| 로봇 시계가 PC와 달라 토픽 시각이 맞지 않습니다 | PC의 `clock_bridge`가 시각을 고쳐 넘김 | |
| 공식 구동 노드는 속도 명령이 끊겨도 마지막 속도로 계속 달립니다 | 로봇의 `cmd_vel_watchdog`가 0.5 s 넘게 명령이 없으면 세움 | |
| 공용 와이파이는 멀티캐스트를 막아 ROS 2가 서로를 찾지 못합니다 | `ROS_STATIC_PEERS`로 상대 IP를 적음 | |
| 와이파이 지연으로 주행 중 감시 노드가 로봇을 세울 수 있습니다 | 감시 노드의 `--timeout`을 늘림 | |
| 바퀴 토크(모터 전류)를 내보내지 않아 부하를 직접 알 수 없습니다 | 가감속 누적으로 추정(`usage.py`) | |
