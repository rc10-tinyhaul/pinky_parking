# 마무리 계획

과정 결과물을 실물 측정으로 채우는 계획입니다. 시나리오(두 트랙, 차선 변경, 주유, 주차)와 코드는 그대로 둡니다.

## 과정 표와 지금 상태

| 결과물 | 상태 | 채우는 곳 |
|---|---|---|
| 자체 ROS2 주행 user 패키지 | 있음 | `pinky_parking_*` 패키지 7개 |
| 파라미터 튜닝 로그 | 없음 | [tuning_log.md](tuning_log.md) |
| 비전 결합 데모 영상 | 없음 | README에 링크 |
| 실측 한계 분석 | 없음 | [limits.md](limits.md) |

일자별 할 일 중 비어 있는 것은 SLAM 실측과 trade-off, Nav2 실측과 trade-off, 비전 결합 시나리오의 실물 검증입니다. 안전 점검(전원·비상 정지 확인, `pinky_start.sh`)과 실물 토픽 시각화 기록은 일부만 됐고, YOLO는 쓰지 않았습니다.

## 순서

### A. 로봇 없이 (먼저)

| 할 일 | 상태 |
|---|---|
| 궤적 파일에 주행 설정, 차종, 실물 여부 남기기 | 브랜치 `syaseuta/trajectory-settings` |
| 궤적 파일을 설정별 표로 뽑기(`scripts/trajectory_table.py`) | 같은 브랜치 |
| 정차 오차를 줄자로 재는 도구(`scripts/park_accuracy.py --manual`) | 브랜치 `syaseuta/park-accuracy` |
| 화면 가장자리에 걸린 마커 거르기 | 브랜치 `syaseuta/marker-edge` |
| 튜닝 로그·한계 분석 틀 | 이 문서와 같은 브랜치 |

### B. 로봇 첫 반나절

| 할 일 | 채우는 것 | 시간 |
|---|---|---|
| 실물 연결 재확인(#14). 로봇의 `pinky_start.sh`를 저장소로 가져오고 전원 스위치·비상 정지 방법을 확인 | 안전 점검 | 45분 |
| RViz와 관제 화면으로 실물 라이다·카메라·바퀴 기록을 띄워 캡처 | 토픽 시각화 | 15분 |
| SLAM으로 강의실 지도를 만들고, 벽 사이 거리를 줄자와 비교 | SLAM 실측 | 1시간 |
| 그 지도로 주행 속도 0.10 / 0.15 / 0.20 m/s를 각 3회: 트랙 한 바퀴와 주차, 시간과 정차 오차 | Nav2 실측, 튜닝 로그 | 1시간 30분 |
| 로봇을 손으로 옮긴 뒤 마커로 위치를 되찾는지, 줄자와 비교 | 비전 결합 시나리오 검증 | 45분 |
| 위 측정을 계속 촬영 | 데모 영상 | 측정 중 |

SLAM은 상자 기지 없이 강의실 벽과 기둥으로 만듭니다. 시연이 정해진 코스 주행과 주차라 가벽이 필요 없습니다(멘토 조언). 지도는 로봇 한 대만 켜고 만듭니다.

### C. 로봇을 한 번 더 쓸 수 있으면

| 할 일 | 채우는 것 |
|---|---|
| SLAM 설정 하나를 바꿔 지도를 다시 만들고 비교 | SLAM trade-off |
| 주시 거리, 도착 허용 거리 비교 | 튜닝 로그 보강 |

못 하면 한계 분석에 "설정 한 가지씩만 비교함"이라고 적습니다.

### D. 측정 뒤

| 할 일 |
|---|
| 튜닝 로그의 고른 값과 이유 채우기 |
| 한계 분석의 실물 칸과 최종 프로젝트로 넘기는 것 채우기 |
| YOLO 결정. 넣으면 공개 모델로 대상 하나를 로봇 카메라 영상에서 인식하는 데까지. 넣지 않으면 한계 분석에 이유 기록 |
| 영상 링크를 README에, 이슈 #8(실물 정차 오차 측정으로 범위 변경)·#12(닫음) 정리 |

## 최종 프로젝트로 넘기는 것

- 새 임무 시나리오, 안 쓰는 코드 삭제, `dataset/` 폴더 처리
- 트레일러를 달고 후진하는 실험(접히기까지의 거리, 트레일러 길이별 차이)
- 정차 오차는 주차 칸에서 재므로, 최종에서 부두가 생기면 그 자리에서 다시 잽니다
